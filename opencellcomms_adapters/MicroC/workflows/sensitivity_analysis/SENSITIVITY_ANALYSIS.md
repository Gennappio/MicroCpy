# p53 Sensitivity Analysis (one factor at a time)

Companion note for the `p53_sa_*.json` workflows in this folder. Each is a
full copy of `../microc_p53_experiment.json` whose **`p53off` Planner arm is
baked into the canvas**, so every Planner tab below is a sparse diff that
changes exactly **one control variable**. The five files are generated by
`build_sensitivity_workflows.py` — regenerate them rather than hand-editing
(see [Regenerating](#regenerating)).

## The baseline (baked into every canvas)

| Mechanism | Owning node (canvas) | Value |
|---|---|---|
| p53 knockout | Gene Knockouts (Agents → tumor_cell_create) | `p53 = false`, clamped for the whole run |
| Cell Height | Setup Domain (World) | 15 µm — the 1000-cell seed (max index radius 18.44) spans **276.6 µm** |
| Domain | Setup Domain (World) | 1500 × 1500 µm, 30 × 30 solver grid (50 µm voxels) |
| Consumption scales | diffusion_step (World) | Oxygen 11, Lactate 11, Glucose 7 |
| Glucose supply | Glucose Substance (JSON) (Resources) | boundary 5.0 mM, initial 5.0 mM, fixed boundary |
| Gene propagation | Propagation Steps (Agents → gene_update) | 5 single-gene updates per step |
| Proliferation gate | Proliferation Gate (Agents → fate_update) | `atp_threshold1 = 0.5`, `cell_cycle_time = 2` |
| Loop | Simulation Steps (Scheduler) | 2000 scheduler steps = a budget of **10 000 single-gene updates per cell** at 5 propagation steps (the baseline experiment runs 500 steps) |
| Snapshots | Plot Interval / Checkpoint Interval (World → iteration_plots) | every 10 iterations = every **50 gene updates**, 200 quadrant plots and checkpoints per arm |

Everything else is the baseline experiment unchanged, except that the
`symbiosis_summary` behaviour is replaced by **`sensitivity_summary`** (the
`Record Sensitivity Metrics` node, which subsumes the symbiosis census) and
`fate_summary` is kept. **Record Lactate Balance**, at the end of `diffusion_step`,
captures lactate exchange for the sensitivity CSV before gene and fate updates.

## The sweeps

| Workflow | Control variable (owning parameter node) | Levels → Planner tabs | Held fixed |
|---|---|---|---|
| `p53_sa_glucose_consumption.json` | Glucose Consumption Scale (`diffusion_step-param_glucose_conversion_factor`) | 5.6 / **7** / 8.4 → `glc_cons_5.6`, `glc_cons_7.0`, `glc_cons_8.4` (±20 %) | oxygen and lactate scales, glucose supply, geometry |
| `p53_sa_oxygen_consumption.json` | Oxygen Consumption Scale (`diffusion_step-param_oxygen_conversion_factor`) | 6.6 / 8.8 / **11** → `o2_cons_6.6`, `o2_cons_8.8`, `o2_cons_11.0` (−40 %, −20 %; 13.2 was numerically unstable, so the sweep runs on the low side) | glucose and lactate scales, supply, geometry |
| `p53_sa_glucose_boundary.json` | Glucose Substance (JSON): `boundary_value` **and** `initial_value` (`glucose_init-param_substances`) | **5.0** / 5.5 / 6.0 mM → `glc_bnd_5.0`, `glc_bnd_5.5`, `glc_bnd_6.0` (+10 %, +20 %; 4.5 mM was numerically unstable, so the sweep runs on the high side) | diffusion coefficient, thresholds, scales, geometry |
| `p53_sa_relative_tumor_size.json` | Size X / Size Y with Grid NX / NY (`envinit-Setup_simulation-param_domain_*`), same seed, 50 µm spacing kept | 900 / 1200 / **1500** µm → `domain_900`, `domain_1200`, `domain_1500` (1800 µm was numerically unstable, so the sweep runs on the small side); initial `relative_tumor_size` = 276.6 / (size/2) = **0.615 / 0.461 / 0.369** | cell height (so the tumour is the same 276.6 µm colony), all consumption and supply values |
| `p53_sa_propagation_steps.json` | Propagation Steps (`gene_update-param_propagation_steps`): single-gene updates per cell per scheduler step | 1 / 10 / 50 → `prop_1`, `prop_10`, `prop_50` (the baseline value 5 is run by `glc_bnd_5.0`, the suite's baseline tab); each tab also sets Simulation Steps to 10 000 / 1 000 / 200 and the plot and checkpoint intervals to 50 / 5 / 1 iterations, so every arm covers the same 10 000 gene updates and snapshots every 50 of them | every field, consumption and gate value; the gene-step budget and snapshot cadence |

The bold level is the baseline: its tab carries **no override** (the
validator warns on redundant copies). Only `glc_bnd_5.0` in
`p53_sa_glucose_boundary.json` is **enabled**; the baseline tabs of the other
three files are present but disabled. With shared pairing, replicate *r* gets
the same seed in every file, so an enabled baseline in each file would repeat
the same ten simulations, not add observations. The one enabled tab runs the
baseline once, and the collector reports it on every axis (below). To move the
baseline to another file, change `BASELINE_OWNER` in the generator and
regenerate. Because the propagation sweep changes
how much gene-network time passes per scheduler step, run length and snapshot
cadence are fixed in gene updates, not iterations: every arm runs
10 000 single-gene updates per cell (scheduler steps = 10 000 / propagation
steps) and snapshots every 50 of them, so `prop_1` runs 10 000 iterations and
`prop_50` runs 200, each with 200 quadrant plots. Every per-iteration CSV
carries `gene_steps` = iteration × propagation steps and the fate-counts plot
uses it as its x axis: arms are compared on the number of gene-network
updates a cell has received, never on scheduler iterations. Note the solver
cost scales with iterations, so `prop_1` takes about five times the baseline
arm's wall time and `prop_50` a tenth. The glucose-boundary sweep moves the
initial value together with the boundary, as the `stab_headroom` experiment
did; the metabolic solve is a steady-state Picard iteration, so the initial
value only seeds the first solve. The geometry sweep keeps the solver spacing
at 50 µm (`nx = size / 50`) because `DomainConfig` requires a square 1–100 µm
grid, and keeps Cell Height at 15 µm so the biological grid (`size / 15` =
60 / 80 / 100) is integral and the centre-relative seed lands on the centre.

The complete replication plan is stored in each workflow's
`metadata.gui.planner` block: **10 replicates**, generated seeds with master seed
**42**, and **shared pairing**. Different seeds provide stochastic replicates;
replaying the same configuration and seed does not add an independent
observation. Change these settings in Planner and save or export the workflow
when designing a different experiment. See the [replication guide](../../../../docs/PLANNER_REPLICATION.md)
for seeding, duplicate baselines and saved output folders.

## What every run records

`Record Sensitivity Metrics` writes one row per scheduler iteration to
`sensitivity_summary/timeseries/sensitivity_metrics_over_time.csv` (rewritten
in full each iteration, like the sibling reporters). Fractions `F_*` are over
`N_total` unless stated; a blank cell means "undefined this iteration".

| Column | Definition | Value owner / source |
|---|---|---|
| `iteration` | scheduler loop counter | executor `loop_iteration` |
| `gene_steps`, `propagation_steps` | `iteration × propagation_steps`, the gene-update clock all arms are compared on; and the step count in effect | Propagation Steps node (gene_update canvas), read at run time from `results['gene_propagation']` published by the Propagate Gene Networks node; blank if no updater ran |
| `N_total`, `N_viable` | all cells; cells whose phenotype is neither Necrosis nor Apoptosis | population |
| `N_proliferating`, `N_quiescent`, `N_growth_arrest`, `N_apoptotic`, `N_necrotic` and `F_*` | phenotype census and fractions (Quiescent and Growth_Arrest are distinct MicroC phenotypes) | fate_update nodes |
| `F_inactive` | `1 − F_proliferating` (every non-proliferating cell; sum the phenotype fractions to split it) | — |
| `N_mitoATP`, `N_glycoATP`, `R_MG` | cells with the gene ON; `R_MG = N_mitoATP / N_glycoATP` (blank when no glycolytic cell) | gene states |
| `N_atp_ok`, `F_ATP`, `atp_threshold1` | viable cells with `atp_rate > atp_threshold1 × atp_rate_max` (the proliferation gate's own law, `atp_gate_passes`), their fraction of `N_viable`, and the threshold in effect | Proliferation Gate table, read at run time from `results['proliferation_gate']` published by `Mark Proliferating Cells (ATP + cell cycle gated)`; blank if that node is absent |
| `N_oxygenated`, `N_hypoxic`, `F_hypoxic`, `hypoxia_threshold_mM` | oxygen-region census (`oxygen_region_census`): hypoxic when Oxygen at the cell < Hypoxia Threshold | **Hypoxia Threshold (mM)** node on the `sensitivity_summary` canvas (0.022 mM = the Oxygen_supply association threshold, so hypoxic ⇔ `Oxygen_supply` input OFF) |
| `MSI_mct1`, `MSI_mito` | metabolic symbiosis index, both readings of "lactate-metabolic" (MCT1 ON / mitoATP ON), the law of `Record Metabolic Symbiosis` (`symbiosis_index`) | shared helper |
| `lactate_production_mol_s`, `lactate_consumption_mol_s`, `lactate_balance_mol_s` | viable-cell production, consumption, and their difference; positive balance means net release, negative means net uptake | **Record Lactate Balance** on `diffusion_step`; reads the metabolism node's rates after the converged solve, before gene/fate updates |
| `glucose_min_mM`, `oxygen_min_mM` | minimum of the whole solver field | diffusion solver |
| `tumor_radius_um` | distance from the domain centre to the farthest cell; position = bio-grid index × Cell Height | Setup Domain (`config.domain`) |
| `domain_size_um`, `relative_tumor_size` | Size X; `tumor_radius_um / (domain_size_um / 2)` | Setup Domain |

Lactate values are total cellular exchange rates in **mol/s**, preserved without
decimal rounding. The snapshot excludes cells already in Necrosis or Apoptosis;
Growth Arrest retains the weight already applied by metabolism. This phase
precedes the phenotype census in the same row. Missing rates, a failed metabolic
solve, or an absent snapshot leave all three columns blank; no viable cells
means zero total exchange. A zero balance can mean either equal production and
consumption or no activity, so retain the two gross totals. The definition lives
in **Record Lactate Balance**; it measures cellular exchange, not domain boundary
flux, lactate accumulation, or proof of functional symbiosis. The collector carries
these columns into the final sensitivity summary automatically.

The run log states every source once (`[SENSITIVITY] sources in effect: …`)
and then prints one compact line per iteration. `fate_summary` still writes
`gene_fate_counts_over_time.csv/.png` alongside; its CSV carries the same
`gene_steps` column and the PNG's x axis is gene-network updates (the axis
label says "scheduler iteration" instead when no updater published a step
count).

## Running

From `opencellcomms_engine/` (the venv active). A plain run executes **every
enabled tab**, one after the other:

```bash
python run_workflow.py --workflow ../opencellcomms_adapters/MicroC/workflows/sensitivity_analysis/p53_sa_glucose_consumption.json --no-observability
python run_workflow.py --workflow ../opencellcomms_adapters/MicroC/workflows/sensitivity_analysis/p53_sa_glucose_boundary.json --planner-tab glc_bnd_4.5   # one arm
```

On the cluster, submit **one SLURM job per suite file** from the repository
root after the one-time environment setup; the five jobs run concurrently and
each writes its own `runs/<workflow name>_<timestamp>/` folder:

```bash
bash run_microc_slurm.sh --install-only      # once on the cluster
for f in opencellcomms_adapters/MicroC/workflows/sensitivity_analysis/p53_sa_*.json; do
    sbatch run_sensitivity_slurm.sh "$f"
done
```

`sbatch run_sensitivity_slurm.sh` with no argument still runs the whole suite
in one job. Either way a job executes its runs sequentially, one process per
replicate. Each job reads the plan from its workflow file: 12 enabled
configurations × 10 replicates = **120 executions** in total (30 + 20 + 20 +
30 + 20), with the baseline run once by the glucose-boundary job. Replicate and
seed settings cannot be overridden on the command line; change Planner and
save the workflow instead.

Results stay in readable configuration/replicate/attempt folders. Each attempt
contains the executed workflow copy and normal simulation outputs. An immutable
execution record is generated automatically inside the results for provenance,
safe retries and duplicate detection; it is output only and is never provided
or edited as a plan. See the [replication guide](../../../../docs/PLANNER_REPLICATION.md#result-folders)
for the folder layout.

Quadrant plots and state checkpoints are drawn every 50 gene updates (the
Plot Interval and Checkpoint Interval nodes on the `iteration_plots` canvas,
10 iterations at 5 propagation steps), so every arm writes 200 PNGs; change
`PLOT_EVERY_GENE_STEPS` in the generator to alter the cadence for the whole
suite at once.

## Collecting

```bash
python opencellcomms_adapters/MicroC/workflows/sensitivity_analysis/collect_sensitivity_results.py            # runs/ -> runs/sensitivity_summary.csv
python opencellcomms_adapters/MicroC/workflows/sensitivity_analysis/collect_sensitivity_results.py --runs /path/to/runs --out summary.csv
```

One row per suite run (identified by the `p53_sa_*` `workflow_source_path` of
the run's `workflow.json`): the control variables read from the executed
workflow (`glucose_conversion_factor`, `oxygen_conversion_factor`,
`glucose_boundary_mM`, `glucose_initial_mM`, `domain_size_x_um`, `nx`,
`cell_height_um`, `propagation_steps`, `steps_planned`), `n_iterations`, the first-iteration
`tumor_radius_um_initial` / `relative_tumor_size_initial`, and every metric
of the last recorded iteration. The `level` column is the swept value of that
run's axis. The ten baseline runs appear once on each of the four axes that
have a baseline level (same `run_id`, `level` 5.0 / 7 / 11 / 0.369); they are
one set of observations, not four. The collector reads the suite files
(`--suite`, default: this folder) to know which tab is the baseline.

## Regenerating

```bash
python opencellcomms_adapters/MicroC/workflows/sensitivity_analysis/build_sensitivity_workflows.py                        # rewrite the five suite files from the baseline
python opencellcomms_adapters/MicroC/workflows/sensitivity_analysis/build_sensitivity_workflows.py --steps 3 --prefix smoke_ --out /tmp/sa_smoke   # short throwaway copies
cd opencellcomms_engine && python scripts/validate_workflow.py ../opencellcomms_adapters/MicroC/workflows/sensitivity_analysis/*.json
```

The generator bakes the baseline's `p53off` overrides with the engine's own
`apply_overrides`, rewrites the two `../data/` paths for this subfolder, sets
`metadata.workflow_source_path` to the repo-relative path (a Planner arm runs
from a temp copy and recovers its directory from it), swaps the reporter, and
writes the Planner tabs and replication settings. Levels and tab names live in
its `AXES` table. Readability
rules for these files are the usual ones: `docs/READABILITY.md`.
