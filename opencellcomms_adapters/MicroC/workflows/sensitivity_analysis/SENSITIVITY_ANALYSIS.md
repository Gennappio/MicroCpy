# p53 Sensitivity Analysis (one factor at a time)

Companion note for the `p53_sa_*.json` workflows in this folder. Each is a
full copy of `../microc_p53_experiment.json` whose **`p53off` Planner arm is
baked into the canvas**, so every Planner tab below is a sparse diff that
changes exactly **one control variable**. The four files are generated by
`build_sensitivity_workflows.py` — regenerate them rather than hand-editing
(see [Regenerating](#regenerating)).

## The baseline (baked into every canvas)

| Mechanism | Owning node (canvas) | Value |
|---|---|---|
| p53 knockout | Gene Knockouts (Agents → tumor_cell_create) | `p53 = false`, clamped for the whole run |
| Cell Height | Setup Domain (World) | 15 µm — the 1000-cell seed (max index radius 18.44) spans **276.6 µm** |
| Domain | Setup Domain (World) | 1500 × 1500 µm, 30 × 30 solver grid (50 µm voxels) |
| Consumption scales | diffusion_step (World) | Oxygen 11, Lactate 11, Glucose 7 |
| Glucose supply | Glucose Substance (JSON) (Resources) | boundary 5.0 mM, initial 5.0 mM, fixed boundary |
| Gene propagation | Propagation Steps (Agents → gene_update) | 5 single-gene updates per step |
| Proliferation gate | Proliferation Gate (Agents → fate_update) | `atp_threshold1 = 0.5`, `cell_cycle_time = 2` |
| Loop | Simulation Steps (Scheduler) | 500 scheduler steps |

Everything else is the baseline experiment unchanged, except that the
`symbiosis_summary` behaviour is replaced by **`sensitivity_summary`** (the
`Record Sensitivity Metrics` node, which subsumes the symbiosis census) and
`fate_summary` is kept.

## The sweeps

| Workflow | Control variable (owning parameter node) | Levels → Planner tabs | Held fixed |
|---|---|---|---|
| `p53_sa_glucose_consumption.json` | Glucose Consumption Scale (`diffusion_step-param_glucose_conversion_factor`) | 5.6 / **7** / 8.4 → `glc_cons_5.6`, `glc_cons_7.0`, `glc_cons_8.4` (±20 %) | oxygen and lactate scales, glucose supply, geometry |
| `p53_sa_oxygen_consumption.json` | Oxygen Consumption Scale (`diffusion_step-param_oxygen_conversion_factor`) | 8.8 / **11** / 13.2 → `o2_cons_8.8`, `o2_cons_11.0`, `o2_cons_13.2` (±20 %) | glucose and lactate scales, supply, geometry |
| `p53_sa_glucose_boundary.json` | Glucose Substance (JSON): `boundary_value` **and** `initial_value` (`glucose_init-param_substances`) | 4.5 / **5.0** / 5.5 mM → `glc_bnd_4.5`, `glc_bnd_5.0`, `glc_bnd_5.5` (±10 %) | diffusion coefficient, thresholds, scales, geometry |
| `p53_sa_relative_tumor_size.json` | Size X / Size Y with Grid NX / NY (`envinit-Setup_simulation-param_domain_*`), same seed, 50 µm spacing kept | 1200 / **1500** / 1800 µm → `domain_1200`, `domain_1500`, `domain_1800`; initial `relative_tumor_size` = 276.6 / (size/2) = **0.461 / 0.369 / 0.307** | cell height (so the tumour is the same 276.6 µm colony), all consumption and supply values |

The bold level is the baseline: its tab carries **no override** (the
validator warns on redundant copies). The glucose-boundary sweep moves the
initial value together with the boundary, as the `stab_headroom` experiment
did; the metabolic solve is a steady-state Picard iteration, so the initial
value only seeds the first solve. The geometry sweep keeps the solver spacing
at 50 µm (`nx = size / 50`) because `DomainConfig` requires a square 1–100 µm
grid, and keeps Cell Height at 15 µm so the biological grid (`size / 15` =
80 / 100 / 120) is integral and the centre-relative seed lands on the centre.

Runs are **stochastic replicates**: the single-gene update draws from Python's
unseeded `random`, so two runs of the same tab differ. The four baseline-level
tabs therefore double as a noise floor for the whole suite. Repeat any arm to
tighten it.

## What every run records

`Record Sensitivity Metrics` writes one row per scheduler iteration to
`sensitivity_summary/timeseries/sensitivity_metrics_over_time.csv` (rewritten
in full each iteration, like the sibling reporters). Fractions `F_*` are over
`N_total` unless stated; a blank cell means "undefined this iteration".

| Column | Definition | Value owner / source |
|---|---|---|
| `iteration` | scheduler loop counter | executor `loop_iteration` |
| `N_total`, `N_viable` | all cells; cells whose phenotype is neither Necrosis nor Apoptosis | population |
| `N_proliferating`, `N_quiescent`, `N_growth_arrest`, `N_apoptotic`, `N_necrotic` and `F_*` | phenotype census and fractions (Quiescent and Growth_Arrest are distinct MicroC phenotypes) | fate_update nodes |
| `F_inactive` | `1 − F_proliferating` (every non-proliferating cell; sum the phenotype fractions to split it) | — |
| `N_mitoATP`, `N_glycoATP`, `R_MG` | cells with the gene ON; `R_MG = N_mitoATP / N_glycoATP` (blank when no glycolytic cell) | gene states |
| `N_atp_ok`, `F_ATP`, `atp_threshold1` | viable cells with `atp_rate > atp_threshold1 × atp_rate_max` (the proliferation gate's own law, `atp_gate_passes`), their fraction of `N_viable`, and the threshold in effect | Proliferation Gate table, read at run time from `results['proliferation_gate']` published by `Mark Proliferating Cells (ATP + cell cycle gated)`; blank if that node is absent |
| `N_oxygenated`, `N_hypoxic`, `F_hypoxic`, `hypoxia_threshold_mM` | oxygen-region census (`oxygen_region_census`): hypoxic when Oxygen at the cell < Hypoxia Threshold | **Hypoxia Threshold (mM)** node on the `sensitivity_summary` canvas (0.022 mM = the Oxygen_supply association threshold, so hypoxic ⇔ `Oxygen_supply` input OFF) |
| `MSI_mct1`, `MSI_mito` | metabolic symbiosis index, both readings of "lactate-metabolic" (MCT1 ON / mitoATP ON), the law of `Record Metabolic Symbiosis` (`symbiosis_index`) | shared helper |
| `glucose_min_mM`, `oxygen_min_mM` | minimum of the whole solver field | diffusion solver |
| `tumor_radius_um` | distance from the domain centre to the farthest cell; position = bio-grid index × Cell Height | Setup Domain (`config.domain`) |
| `domain_size_um`, `relative_tumor_size` | Size X; `tumor_radius_um / (domain_size_um / 2)` | Setup Domain |

The run log states every source once (`[SENSITIVITY] sources in effect: …`)
and then prints one compact line per iteration. `fate_summary` still writes
`gene_fate_counts_over_time.csv/.png` alongside.

## Running

From `opencellcomms_engine/` (the venv active). A plain run executes **every
enabled tab**, one after the other:

```bash
python run_workflow.py --workflow ../opencellcomms_adapters/MicroC/workflows/sensitivity_analysis/p53_sa_glucose_consumption.json --no-observability
python run_workflow.py --workflow ../opencellcomms_adapters/MicroC/workflows/sensitivity_analysis/p53_sa_glucose_boundary.json --planner-tab glc_bnd_4.5   # one arm
```

Results land in `runs/<file stem>_<tab>/`, e.g.
`runs/p53_sa_glucose_boundary_glc_bnd_4.5/sensitivity_summary/timeseries/sensitivity_metrics_over_time.csv`,
next to `fate_summary/`, `iteration_plots/` and the executed `workflow.json`
(overrides baked in). GUI runs of the same file land in `runs/<tab>/`; tab
names are unique across the suite so the four files never overwrite each
other.

SLURM: `run_sensitivity_slurm.sh` (repo root) submits the whole suite as a
job array, one task per arm, each delegating to `run_microc_slurm.sh` with
`--no-observability`:

```bash
mkdir -p slurm_logs
bash run_microc_slurm.sh --install-only      # build .venv-hpc once, before the array
bash run_sensitivity_slurm.sh --list         # index -> workflow, tab
sbatch run_sensitivity_slurm.sh              # all 12 arms in parallel
sbatch --array=0-11%4 run_sensitivity_slurm.sh   # at most four at a time
```

Logs go to `slurm_logs/microc_p53_sa_<jobid>_<index>.out`. A single arm can
still be run through the plain launcher:

```bash
MICROC_WORKFLOW="$PWD/opencellcomms_adapters/MicroC/workflows/sensitivity_analysis/p53_sa_glucose_consumption.json" \
  sbatch --job-name=sa_glc_cons_5.6 run_microc_slurm.sh glc_cons_5.6
```

Per-iteration quadrant plots and state checkpoints are inherited unchanged
from the baseline (`iteration_plots`, `plot_interval` 1), so a 500-step arm
writes 500 PNGs; raise `plot_interval` on that canvas if disk or time matter.

## Collecting

```bash
python opencellcomms_adapters/MicroC/workflows/sensitivity_analysis/collect_sensitivity_results.py            # runs/ -> runs/sensitivity_summary.csv
python opencellcomms_adapters/MicroC/workflows/sensitivity_analysis/collect_sensitivity_results.py --runs /path/to/runs --out summary.csv
```

One row per suite run (identified by the `p53_sa_*` `workflow_source_path` of
the run's `workflow.json`): the control variables read from the executed
workflow (`glucose_conversion_factor`, `oxygen_conversion_factor`,
`glucose_boundary_mM`, `glucose_initial_mM`, `domain_size_x_um`, `nx`,
`cell_height_um`, `steps_planned`), `n_iterations`, the first-iteration
`tumor_radius_um_initial` / `relative_tumor_size_initial`, and every metric
of the last recorded iteration. The `level` column is the swept value of that
run's axis.

## Regenerating

```bash
python opencellcomms_adapters/MicroC/workflows/sensitivity_analysis/build_sensitivity_workflows.py                        # rewrite the four suite files from the baseline
python opencellcomms_adapters/MicroC/workflows/sensitivity_analysis/build_sensitivity_workflows.py --steps 3 --prefix smoke_ --out /tmp/sa_smoke   # short throwaway copies
cd opencellcomms_engine && python scripts/validate_workflow.py ../opencellcomms_adapters/MicroC/workflows/sensitivity_analysis/*.json
```

The generator bakes the baseline's `p53off` overrides with the engine's own
`apply_overrides`, rewrites the two `../data/` paths for this subfolder, sets
`metadata.workflow_source_path` to the repo-relative path (a Planner arm runs
from a temp copy and recovers its directory from it), swaps the reporter, and
writes the tabs. Levels and tab names live in its `AXES` table. Readability
rules for these files are the usual ones: `docs/READABILITY.md`.
