# 2.4 One File, One Node

The one-file-one-node rule is central to OpenCellComms.

Each atomic biological operation is implemented as one Python function in one file,
and that function appears as one node in the workflow. A node may represent
"consume oxygen", "migrate", "secrete TNF", "diffuse oxygen", "plot world", or
"write run summary".

This rule has several advantages.

For the biologist, it makes the model readable. Opening a node shows a small
function with one purpose, rather than a long script containing many processes.

For the GUI, it makes the model composable. Nodes can be placed, reordered, disabled,
or parameterized.

For the coding agent, it reduces the generation task. The agent does not need to
write a whole simulator at once. It writes one biological operation at a time.

For validation, it gives every operation an identity. A function can be checked,
homed, scheduled, observed, and explained individually.

This is why OpenCellComms does not encourage large generated scripts. Large scripts
may be easier to produce in one pass, but they are harder for biologists to review
and harder for validators to reason about.
