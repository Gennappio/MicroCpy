# 2.2 Make Models Visible and Editable

Generated code is not enough. A biologist must be able to see what the model does.
OpenCellComms therefore treats the workflow as a visible scientific object.

The GUI organizes a model into tabs that match biological questions:

- What is the world?
- Which agents exist?
- Which resources or signals exist?
- What happens during initialization?
- What happens each scheduler step?
- What outputs and summaries are produced?

This matters because the GUI is not just decoration. It is the biologist's way to
interrogate the generated model. If a behavior cannot be found in the GUI, then even
if it runs, it is not a good scientific artifact. It is hidden biology.

For this reason, OpenCellComms enforces that runnable behaviors have visible homes.
The model must remain navigable, not only executable.
