# 5.1 The No-Orphan Rule and Navigable Ontology

The no-orphan rule says that every behavior that can run must also have a visible
home in the GUI.

If the scheduler calls a behavior, that behavior must be listed under a real,
clickable category: an agent kind, a resource kind, the world, or processing.
In-loop behaviors are homed on the object that owns them. For example, a per-cell
gene update is something the cell does each step, so it belongs under that cell
kind. Post-loop behaviors, such as reports or final plots, belong under Processing.

An orphan behavior is reachable from execution but belongs to no tab. It may run
correctly, but the biologist has no obvious place to find, inspect, or edit it. This
is a serious failure mode: the model can execute while becoming illegible.

OpenCellComms machine-checks against this failure. A model is not considered well
structured if it contains runnable biology that is invisible to the biologist.
