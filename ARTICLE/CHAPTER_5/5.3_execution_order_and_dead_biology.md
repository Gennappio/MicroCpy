# 5.3 Execution Order and Dead Biology

A workflow node can be visible but not executed. This happens when a node exists on
a canvas but is omitted from `execution_order`.

This failure is especially dangerous because the model looks complete. The biologist
can see the node, and the coding agent may have written the function, but the
runtime never calls it.

OpenCellComms treats this as a semantic warning. If a subworkflow has a non-empty
execution order, enabled nodes should appear in that order. Otherwise they are dead
biology: biological logic present in the model artifact but absent from the run.

The GUI also uses canonical execution edges so that button-added calls in
Initialization and Scheduler survive export into the executable workflow.
