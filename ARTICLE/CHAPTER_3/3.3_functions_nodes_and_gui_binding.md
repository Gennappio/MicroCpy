# 3.3 Functions, Nodes, and GUI Binding

In OpenCellComms, a Python function becomes useful to the biologist when it is
registered and placed as a node. The node is the visible representation of the
function in the GUI.

The node carries:

- the function name;
- configurable parameters;
- a position on the canvas;
- execution order connections;
- optional contract metadata describing what it reads and writes.

The workflow connects nodes into subworkflows. A subworkflow is a small canvas: for
example, a tumor-cell step canvas may contain "consume oxygen", "check hypoxia",
and "emit death intent".

The GUI binding is what makes generated code inspectable. If the coding agent writes
a function but does not place it in a workflow, the biologist cannot use it. If the
agent places it in a workflow but does not home the behavior to a tab, the model may
run but become invisible. The binding between code, node, workflow, and GUI category
is therefore part of correctness.
