# 3.2 Workflows as Experiments

A workflow is not the same thing as a plugin. A workflow is an experiment.

Conceptually, a workflow answers the question:

> Which available biological operations run, in what order, with what parameters?

The workflow stores:

- the world setup;
- the agent kinds;
- the resource kinds;
- the initialization sequence;
- the scheduler;
- processing and result steps;
- parameter values;
- the execution order of nodes.

This means two workflows can use the same plugin but represent different scientific
experiments. One workflow may disable a behavior, change a parameter, add a report,
or reorder a process. The underlying functions remain reusable.

This separation is useful for biologists because it makes experiments shareable as
workflow JSON files. A collaborator can inspect the workflow and see how the
experiment was assembled, without first reading every Python function.
