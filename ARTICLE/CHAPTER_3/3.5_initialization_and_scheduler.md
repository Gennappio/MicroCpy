# 3.5 Initialization and Scheduler

OpenCellComms separates what happens once from what happens repeatedly.

Initialization builds the model state. It creates the world, initializes resources,
creates agents, and prepares any state needed before the first simulation step.

The Scheduler defines the repeated loop. Each scheduler step runs the behaviors in
the order specified by the workflow. Agent behaviors are called through a per-agent
ask. Resource behaviors update fields. World or reconciliation behaviors commit
intents and update shared state. Processing nodes may run after the loop.

This separation is essential for ABMs. Creating agents is not the same as asking
agents to behave. Initializing a resource is not the same as diffusing it each
step. Writing a final summary is not the same as changing the model.

By making these phases explicit, OpenCellComms prevents coding agents from mixing
setup, behavior, and reporting in one opaque script.
