# 1.1 The Problem for Biologists

Biologists often know the mechanism they want to test. They can state that tumor
cells consume oxygen, immune cells secrete a chemokine, cells die under hypoxia, or
a gene network changes phenotype. The challenge is not always conceptual biology.
The challenge is turning that biology into maintainable simulation software.

In a conventional code-first workflow, important model decisions become hidden in
the implementation:

- where initialization happens;
- which order processes run in;
- whether a rule runs once globally or once per agent;
- where parameters are stored;
- which outputs are produced;
- how different model components communicate.

These are scientific decisions, but they become programming details. A biologist who
wants to change the model must read the code deeply enough to know where those
decisions are encoded. Even experienced programmers can be overwhelmed by generated
simulation code when it is not organized around the biological ontology.

The result is a mismatch: the biologist thinks in terms of cells, resources, signals,
worlds, rules, and outputs, while the software may be organized as functions,
classes, loops, folders, and hidden state. OpenCellComms tries to close this gap by
making the biological organization visible in the software itself.
